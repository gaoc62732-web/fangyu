# 中国数据来源、对象结构与构建流程改造方案

日期：2026-10-14。状态：方案，尚未实施数据迁移。

本方案依据当前中国目录、边界获取和处理脚本、前端读取链路及既有边界规则制定。本次只编写方案，没有下载数据、改动运行数据、执行构建或测试。其他国家的数据整理暂不纳入本轮。

## 1. 对需求的理解与本方案的选择

目标是让维护者直接看清楚：某项数据由谁维护、正式存在哪里、哪些步骤会改变它、更新后影响哪些输出。当前混在大型 JSON、研究材料、特殊脚本与前端逻辑中的职责，需要重新划分。

采用三种维护方式：

1. **人工维护（manual）**：允许最初从网络导入，接管后只编辑本地正式数据；日常构建和更新命令都不重新抓取它。例如文保名录、政区目录、点位描述和已确认坐标。
2. **固定数据（fixed）**：将已取得资料转换成可直接使用的正式数据，以后不再自动更新，也不再重复执行取得它所需的转换。例如白云鄂博矿区替代面、南海段线、目前采用的天地图局部边界。
3. **网络更新（remote）**：负责以后持续获取的来源，目前主要是中国相关 OSM 行政关系、下级街道乡镇、海岸、岛屿及其他规则依赖的 OSM 要素。只有这一类维护来源更新版本。

最终流程为：

```text
第三类网络来源
  → 统一获取并留档
  → 仅依赖该来源的转换、去重、结构整理
  → 第三类正式来源版本
                          ┐
第一类人工维护数据 ───────┼→ 离线组装、跨来源规则 → 前端/API 直接读取的发布包
第二类固定数据 ──────────┘
```

接受直接修改现有前端、API、领域模型、个人记录及导入导出契约。不设计旧格式兼容层、不维持新旧双轨、不保留为兼容而存在的 UUID 映射和旧接口。既有稳定编号若本身合适，可以直接沿用；沿用的理由是避免无意义的身份重建。

对原设想补充五点：

- **维护方式按数据集及字段职责划分。** 同一旧文件可能同时含有人工归属、固定替代面和动态 OSM 面，应先拆开，不能因为文件来自网络就全部归入第三类。
- **固定输入和总体连接仍是两回事。** DataV 坐标转换只做一次，但新达茂旗 OSM 面扣除固定白云面仍须在每次相关更新后重新计算。整区历史结果不能代替这条规则。
- **来源版本与发布指纹分开。** 第一、二类不建立日期版本目录；仍记录来源、结构版本和内容哈希，发布包仍有内容指纹，以便缓存和识别输入组合。这不要求为第一、二类维护独立更新历史。
- **统一字段不等于所有对象使用一个万能对象。** 政区、记录条目、实体地点、来源要素、几何和规则使用各自的明确结构，共享必要的基础字段。
- **人工可读的维护格式与前端传输格式分别设计。** 人工数据分文件、缩进保存；发布时允许合并、压缩、建立索引和生成瓦片，避免把编辑便利转变成浏览器的大量请求。

## 2. 当前流程需要消除的问题

| 现状 | 影响 | 改造方式 |
| --- | --- | --- |
| `data/catalog/catalog.json` 既像人工源，又是前后端成品 | 更新目录、来源迁移和前端打包互相牵连 | 把它改为纯构建输出，人工源独立保存 |
| 下载脚本读取当前目录和当前几何，并可直接覆盖运行文件 | 一次下载依赖上一次成品，难以从明确输入重建 | 获取只写第三类来源版本，构建才读取正式输入 |
| OSM 缓存散在 `data/tmp/osm-china*`、`china-boundary-review` 和 `sources/` | 同一个 relation、way 或响应重复保存、重复转换 | 一个原始响应库、一个来源要素池、多个角色引用 |
| `reviewed-patches`、`published-overrides`、裁剪后的全区面并存 | 很难判断哪一份才是正式来源 | 拆成固定局部几何、人工规则及可删除的构建结果 |
| `retainReviewedChinaGeometry()` 用整区旧面覆盖新导入结果 | 已校订沿海或局部政区的其余 OSM 边界也可能停止更新 | 用有明确范围的替换、相减、合并规则重新组装 |
| 边界选项脚本同时创建政区、修复边界、处理海岸和生成变体 | 身份、源数据、政策和输出耦合 | 政区只由人工目录定义；规则只消费已存在身份 |
| 构建依赖临时研究目录和大型 `research` 包 | 正常启动需要了解历史调查过程 | 构建只读登记过的正式数据集 |
| 中国机场需在运行时借世界条目坐标，并导入研究关联文件 | 点位位置藏在跨目录业务选择器中 | 将确认的位置及来源一次性纳入中国正式地点数据 |
| `code`、`coordinateStatus`、代表点等语义分散在字段和字符串中 | 前端靠字符串推断点位资格与身份 | 使用结构化外部标识和有判别字段的位置类型 |
| 全部国家共用的大型指纹会牵动中国瓦片重建 | 改一条目录或其他国家数据可能重做中国地图 | 分开计算目录、来源处理、边界组装和瓦片依赖 |

边界来源整理只迁移当前采用的规则。`已发现问题记录.md`、飞地清单中的待查问题不会因结构迁移被视为已经解决，也不在本轮自动改变归属。

## 3. 当前中国数据的分类

### 3.1 第一类：人工接管

| 对象 | 迁入内容 | 后续维护 |
| --- | --- | --- |
| 政区身份与目录树 | 现有中国编号、名称、别名、代码、层级、父级、历史状态、管理区身份 | 人工维护；OSM 只提供候选信息，不自动改名、发号或改归属 |
| 14 类中国目录 | 文保、博物馆、景区、遗产、公园、交通等全部现有条目和组成关系 | 按类别、必要时再按省份分文件 |
| 城市称号与认定 | 历史文化名城等认定及有效范围 | 认定只存一次，继承显示由程序生成 |
| 现有点位位置 | 台铁的 244 个直接坐标、17 个机场直接坐标及已确认的其他位置资料 | 本地人工接管，不再自动抓台铁、民航等来源 |
| 机场定位结果 | 已确认的 260 条中国机场定位关联所用坐标、来源标识和限制 | 一次性从现有数据转入中国地点对象，取消对世界目录的运行时位置依赖 |
| 身份及来源映射 | 政区编号到 OSM relation/街道组合的确认映射，地点到官方编号等映射 | 明确字段维护，不按名称隐式重新匹配 |
| 特殊边界与显示规则 | 开关定义、归属、局部作用范围、岛屿划转、父级汇总方式 | 人工规则文件；更新数据不得自行改变规则 |
| 成就与固定榜单 | 已采用的目标、地区关系、2025 赛迪榜单及说明 | 人工维护；不属于实时排名数据 |

中国目录中的无坐标项目继续作为正式条目存在，位置明确写为缺失。中国世遗现有的 245 条国内记录没有可靠 UNESCO 身份桥接，迁移时保留这一事实，不按同名补坐标。中国机场的 36 条暂缓定位记录也保留缺失原因。

这里不额外核验或新增网络资料。第一类接管后的来源不完整项明确记录为 `legacy-unattributed`，并保留原条目内容；不猜造官方来源。

### 3.2 第二类：处理一次后固定

| 对象 | 正式保留物 | 一次性处理后可清理的旧物 |
| --- | --- | --- |
| DataV 白云鄂博矿区 | 已转为 WGS84 的白云鄂博面及来源说明 | 原始 GCJ-02 数据、临时转换结果、该项专用转换流程 |
| 南海段线 | 当前实际采用的十段 `MultiLineString`，独立命名数据包 | 为取得它而保存的天地图完整省级 BIN、重复抽取结果 |
| 天地图局部替代边界 | 当前使用的局部面/线、替换窗口及来源说明 | BIN、解码中间件输出、未参与正式结果的大范围重复面 |
| 现有港澳保留分区 | 当前确实使用、又没有纳入动态替代的分区几何及来源说明 | 与正式保留分区相同的旧运行副本 |
| 其他仍被采用的非 OSM 补充面 | 有名称、用途和作用范围的正式几何资产 | 取得或转换该资产的临时缓存及草稿 |

固定包保留：来源 URL、已知取得时间、许可/署名、原坐标系、已经完成的转换说明、原件哈希（已有时）和正式结果。一般不再保留第一、二类的原始大文件和中间格式。

需要特别避免两种误归类：

- OSM 下级面拼成的汉南、文登、园区、岛屿范围等，即使现在已经拼好，仍属于第三类输入与第一类组合规则，以便跟随 OSM 更新。
- 海岸掩膜、OSM 岛屿面、由当前县面派生的市省面都属于可重建结果，不能为了减少计算而改成永远固定的第二类数据。

### 3.3 第三类：持续获取的 OSM 数据

第三类必须包括普通边界及特殊规则依赖的全部 OSM 输入：

- 中国相关省、市、县行政关系及其完整成员图。
- 汉南、文登、蔡甸、苏州工业园区等规则使用的街道、乡镇关系。
- 深汕、呼中、新林、加格达奇、松岭等管理范围所用要素。
- 唐古拉相关藏青县级关系及接缝处理依赖的邻县。
- 大陆、海南、台湾、港澳及离岛的 `natural=coastline`。
- 群岛关系、岛屿成员和定位所需要素；成员范围从已下载要素计算，不再专门重下同一要素的 bounds。
- 当前规则确实引用的其他 OSM 要素。

纯历史调查用的争议参考关系和河流定位资料不默认进入周期更新。只有正式规则实际消费的数据，才加入统一获取清单；待查材料另有明确用途登记。

### 3.4 三类以外的文件角色

三类表示“正式输入的维护方式”，不强行覆盖全部磁盘文件：

- **原始下载留档**：第三类的原始响应，以内容哈希去重保存。
- **临时文件**：下载分片、失败任务、处理中间数据，可删除。
- **派生及发布结果**：运行几何、变体、索引、压缩包和瓦片，全部由正式输入生成。
- **在线底图配置**：OpenFreeMap、天地图道路/注记/卫星服务独立登记为在线服务。其背景地名不进入本地政区或点位目录，也不承诺能够离线重建服务端数据。
- **个人旅行记录**：引用正式对象身份，独立保存；数据整理和清理不触及个人存档。

## 4. 建议的目录布局

以下为目标结构示意，不要求建立空目录或为每一个小字段新建文件。

```text
data/
  registry.json                      # 正式数据集清单：唯一入口
  sources.json                       # 来源登记：名称、URL、许可、署名
  manual/china/
    regions/                         # 省份分片，含管理区、历史条目
    categories.json
    items/<category>/                # 按类别；大类再按省份分片
    places/                          # 已确认实体地点与位置
    relations.json                   # 组成、包含、位置证据等明确关系
    source-bindings.json             # 目录身份与外部来源要素绑定
    rules/                           # 特殊边界、显示开关、组装规则
    achievements/                    # 成就与榜单
    pending.json                     # 尚未定位/未解决的问题及原因
  fixed/china/
    datav-baiyun/asset.json
    datav-baiyun/geometry.geojson
    south-china-sea-dashes/asset.json
    south-china-sea-dashes/geometry.geojson
    tianditu-local-boundaries/        # 仅现用局部几何与说明
    hkmo-retained-subareas/
  remote/china/osm/
    request-plan.json                # 获取范围与来源对象需求
    current.json                     # 指向当前可用来源版本
    versions/<source-version>/
      manifest.json                  # 实际快照、获取记录、处理工具与内容哈希
      features/                      # 规范化来源要素；成员几何不按角色复制
      coast/                         # 来源内部拼接的岸线、陆地面与未闭合片段
  archive/osm/
    responses/<sha256>.json          # 原始响应字节，去重并长期本地留档
    requests/                       # 查询与响应、快照的对应关系
  generated/
    staging/                         # 未完成更新/构建；正常使用不读取
    china/                           # 当前成功组装结果及构建清单
    web/                             # 前端公共资源；保留现有发布目录入口也可
    packages/                        # 按需生成的数据分发包
```

职责约束：

- `manual` 是日常人工编辑入口，`fixed` 只保存已固定资产。
- `remote` 仅保存第三类当前来源版本及清单；每个版本不再复制完整原始响应。
- `archive/osm` 存原始输入，不参与日常构建和瓦片清理。相同字节只留一份，不保留同一响应的多路径拷贝。
- `generated` 全部可删除重建，任何人工修改都不应只落在此处。
- 第一、二类不建立历史版本目录。第三类处理产物在新版本成功接管后仅保留当前成功版本；原始 OSM 留档仍保留。这样与项目此前“原始 OSM 留档、处理结果仅保留最新成功版”的决定一致。
- 第一、二类原件及转换中间数据按本次新要求完成固化后清理；保留来源元数据与最终几何即可，不继续沿用旧方案中全量保存非 OSM 原件的要求。

## 5. 对象与字段设计

### 5.1 共用结构与约定

采用 **TypeScript 类型 + JSON Schema** 描述维护格式，以 JSON Schema 作为跨 Python/Node 的文件结构依据；Python 使用普通结构读取，无需引入数据库、ORM 或复杂继承框架。

共同约定：

- 固定字段名，使用 `null` 表达没有值，数组没有内容时使用 `[]`。
- 已知编号放入结构化 `identifiers`，不再从名称前缀、description 或状态字符串中解析。
- 对象身份与 OSM relation、行政代码、IATA、UNESCO 编号分开。来源 ID 发生变化时更新映射，不自动生成新的业务对象。
- 人工对象按稳定 ID 排序、固定字段顺序、UTF-8、两空格缩进。按类别和省份拆文件，避免 35 MB 巨型目录成为编辑入口。
- 几何遵循 GeoJSON/WGS84 `[经度, 纬度]`。人工点位位置采用具名 `longitude`、`latitude`，发布时转成 GeoJSON。
- 元数据尽可能放在数据集级，个别对象通过 `sourceRefs` 引用或覆盖，避免数千次重复同一来源描述。
- 可选字段只用于确实可选的信息；不同对象种类必须有明确判别字段，不用几十个可选字段拼成万能条目。

```ts
type Maintenance = 'manual' | 'fixed' | 'remote';

interface Dataset<T> {
  schemaVersion: 1;
  id: string;
  maintenance: Maintenance;
  scope: 'china';
  sourceRefs: string[];
  items: T[];
}

interface Source {
  id: string;
  name: string;
  url: string | null;
  license: string | null;
  attribution: string | null;
  note: string | null;
}

interface ExternalIdentifier {
  system: string;       // cn-admin、osm-relation、iata、unesco 等
  value: string;
  sourceRef: string;
}
```

`schemaVersion` 是结构约定，`sourceRefs` 是来源引用，都不是数据更新版本。来源未知时引用 `legacy-unattributed`；不将“旧目录”包装成已查证的官方资料。

### 5.2 政区 Region

```ts
interface Region {
  id: string;
  name: string;
  aliases: string[];
  kind: 'administrative' | 'management-area' | 'historical';
  level: 'province' | 'city' | 'county';
  parentId: string | null;
  parentRole: 'administrative' | 'catalog';
  identifiers: ExternalIdentifier[];
  sourceRefs: string[];
}
```

- `parentId` 表达人工维护的基础目录关系，`parentRole` 说明它是否代表行政隶属；不把所有管理区的目录父级冒称为法定归属。
- 实际管理、名义归属和显示归属的差异，由有类型的关系/边界规则表达。
- 特殊开关只产生显示投影，不删除 Region，也不把被隐藏 Region 的 ID 重写为另一政区 ID。
- 历史对象可保留供历史内容使用，构建现行行政面时排除；这不要求保留旧数据格式或旧记录兼容代码。
- 直辖市、省直辖县、直筒子市、港澳等“同一面在多个地图层显示”的需求属于渲染关系，不复制 Region 对象。

### 5.3 目录条目 Item 与地点 Place

目录条目表示可被独立记录、认定或列示的对象；地点表示其对应的实体位置。文保项目可能有多个组成地点，线路也可能没有单点位置，二者不强行等同。

```ts
interface Item {
  id: string;
  name: string;
  aliases: string[];
  categoryIds: string[];
  regionIds: string[];
  placeId: string | null;
  identifiers: ExternalIdentifier[];
  sourceRefs: string[];
  details: ItemDetails;             // 按类别判别的结构，不使用无类型任意字典
}

interface Place {
  id: string;
  name: string;
  aliases: string[];
  location: Location;
  identifiers: ExternalIdentifier[];
  sourceRefs: string[];
}

type Location =
  | { status: 'missing'; reason: string }
  | {
      status: 'available';
      kind: 'site-point' | 'entrance' | 'project-reference' | 'area-reference';
      position: { longitude: number; latitude: number };
      sourceRef: string;
      method: 'source-coordinate' | 'manual' | 'derived-interior-point';
      note: string | null;
    };
```

`ItemDetails` 为文保批次、机场运营说明、铁路站代码等分别定义小结构；实现时只迁移现有信息，不为每条记录制造空字段。类别间相同的来源、坐标和标识字段使用共同定义。

采用下列语义：

- 默认由 `Item.id` 标识一份到访记录，取消目前“展示行 ID + `recordId`”反复间接查找的结构。
- 确认属于同一记录主体的多个分类/多个政区，放入同一个 Item 的 `categoryIds`、`regionIds`；列表只是展示投影。
- 现有多份独立记录只确认位置相同的，可以引用同一个 Place，仍是不同 Item。迁移机场坐标关联不自动合并记录主体。
- 未确认同一实体的同名条目保持独立，不借破坏性改造之名完成推测性去重。
- 父项目与组成地点用关系表连接，子项若可独立记录则使用正式 Item；不再同时维护 `subitems`、多套项目内嵌子项和临时跨表索引。
- 前端使用 `Location.kind` 确定标记样式和用途。项目代表点可明确展示为代表位置，不能作为入口或全部组成地点到访的依据。
- 机场的 IATA 放进 `identifiers`；世界数据的来源证据在中国正式数据中完整登记，之后中国构建不读取世界目录。

在当前页面中，区域地图和点位地图都关闭了旧“已到访机场/世遗”选择器的叠加输出；260 条机场关联目前属于已有定位资料，不能等同于点位页面已绘制的 260 个点。新模型让已确认位置能通过统一点位读取链路使用，这是迁移后需要明确落地的行为。

### 5.4 对象关系 Relation

关系统一存 ID 引用，不在父子两侧各维护一份重复列表：

```ts
interface EntityRef {
  type: 'region' | 'item' | 'place';
  id: string;
}

interface Relation {
  id: string;
  type: 'component-of' | 'contains' | 'overlaps' | 'managed-by';
  from: EntityRef;
  to: EntityRef;
  sourceRefs: string[];
  note: string | null;
}
```

“共享地点”“共享记录”“属于同一父项目”“地理覆盖”分别表达，不由同名、相同坐标或几何相交隐式推断。继承的城市称号、路径名、上下级索引和分组统计都在构建或运行时派生，不回写维护源。

### 5.5 来源要素与目录绑定

第三类规范化要素保存来源事实，不绑定当前前端层级：

```ts
interface SourceFeatureProperties {
  sourceRef: string;
  externalId: string;               // 例如 relation/7363853
  objectVersion: number | null;     // OSM 对象版本，取得时保留
  role: 'administrative' | 'coastline' | 'island-group' | 'supporting';
  name: string | null;
  adminLevel: string | null;        // 原 OSM admin_level，不当作项目层级
}

interface SourceBinding {
  id: string;
  regionId: string;
  sourceFeatureRefs: string[];
  assembly: 'single' | 'union';
  sourceRefs: string[];
  note: string | null;
}
```

规范化几何使用标准 GeoJSON Feature，属性遵循上面的统一结构；其他实际参与规则的 OSM 标签集中列白名单保留。原始下载仍保存完整标签与成员。

现有中文名称、代码、层级及旧边界重叠规则仅用于首次导出绑定表、或以后发现缺失绑定时生成候选。日常构建直接按确认绑定取来源对象，不再每次对全国做名称与 bbox 猜测。relation 重建、成员缺失或映射冲突进入明确待处理项，不能静默选另一个同名面。

### 5.6 固定资产与边界规则

固定资产用人能读懂的稳定名称，例如 `china-datav-baiyun`、`china-south-china-sea-dashes`，不使用随机哈希作为人工引用名。资产描述记录正式几何路径、几何角色、来源、坐标系及已完成的一次性处理。

规则只支持现有需求用到的有限操作，不设计可执行任意代码的 JSON 语言：

| 操作 | 用途 |
| --- | --- |
| `use` / `union` | 取一个来源面或拼接街道、乡镇 |
| `replace-within` | 在明确窗口内采用固定局部几何，窗口外保留新来源 |
| `subtract` | 白云面从新达茂旗面中扣除等 |
| `transfer` | 将某岛屿/管理范围从一组政区划转到另一组，处理相关祖先 |
| `clip-land` | 按当前 OSM 陆地范围裁剪行政面 |
| `aggregate` | 从规定子集更新父级范围；允许保留范围外原父面 |
| `derive-line` | 由当前几何生成国界或名义边界线 |
| `choice` | 定义开关的不同投影及其影响对象 |

规则必须具备 `id`、操作类型、输入引用、目标、依赖、作用范围、原因和来源引用。各操作有独立 Schema，由现有 GIS 函数实现；复杂海岸图构建留在来源预处理代码中，不写成冗长 JSON 运算表达式。

白云鄂博矿区的规则可以表达为：

```json
{
  "id": "china-baiyun-damao-cutout",
  "operation": "subtract",
  "targetRegionId": "CN150223",
  "base": { "dataset": "china-osm", "binding": "region-CN150223" },
  "subtract": { "dataset": "china-datav-baiyun", "feature": "baiyun" },
  "dependsOn": [],
  "reason": "用固定白云鄂博面形成与新达茂旗边界一致的孔洞"
}
```

固定白云面本身直接用于白云政区。无需重下 DataV、重做 GCJ-02 转换，也不保存每次 OSM 更新前的整个达茂旗旧面。

## 6. 第三类的获取与固化流程

### 6.1 一份获取计划，覆盖普通与特殊需求

普通行政面、街道乡镇、唐古拉、岛屿和海岸由同一个任务入口生成获取计划。需求来源是正式绑定和规则依赖，旧 `.overpass` 文件不再各自作为一个长期维护的入口。

计划首先合并全国行政关系及特殊关系的 ID，再按实际接口容量分批获取。不能把“只获取一次”理解为强制一条全国 Overpass 查询：允许空间分片与失败重试，但已完整取得的对象和成员不在其他业务任务中重复获取。

- relation、way、node 在同一快照下按对象类型、ID 和版本归并。
- 同一 relation 同时被省级导入、汉南拼接或边界开关引用时，只转换一份。
- 已有完整成员图时不再先取 `out geom` 再无条件抓取全后代；确有缺件时只补缺失依赖。
- 群岛 members、bounds 和独立岛屿处理共用要素池，bounds 本地计算。
- 不再运行独立的“争议参考全量下载”“海岸缺口历史批次”等与当前计划无关的抓取入口。

### 6.2 获取版本与快照一致性

新版本使用固定 `sourceVersion` 和尽可能一致的 OSM 数据快照时间。支持历史时间查询时，分片使用同一个 `[date:...]`；在来源无法保证同一时刻时，manifest 如实保存各批次时间，不宣称单一快照。

迁移现有混合日期输入时，将其登记为“由已存响应导入的组合版本”，记录组成来源及取得时间范围，禁止伪造为最新全国快照。首次结构迁移可离线完成，不强制为改目录重新联网下载。

新版本的请求键包含来源、标准化查询、快照时间。相同请求成功后直接复用归档；新快照允许重新获取同一 ID，这是更新本身所需。

原始响应以未改写的原始字节归档，查询、时间戳和内容哈希单独记录。业务元数据不再注入下载响应；不要用文件名相同或文件存在来代替“同一快照的完整请求已经完成”。

某版本的覆盖由清单显式列出。完整成功但某关系确实不存在，属于来源缺失；网络超时或不完整返回，属于获取失败。二者不能混为一谈，更不能自动把上版旧面带入而将整体标记为最新。

### 6.3 来源内部预处理

以下步骤只读当前 OSM 原始输入，不读取旧发布几何：

1. 合并并去重 OSM 对象；整理成员依赖、缺失对象和对象版本。
2. relation 转 Polygon/MultiPolygon，保留孔洞、多部件及必要来源标识。
3. 规范名称/字符与坐标结构；保留原名称，不依靠简繁转换重新分配实体身份。
4. 海岸按共享节点和方向拼接，生成陆地面与岸线；未闭合碎片明确登记，不靠就近吸附或随意封口造岛。
5. 行政要素、岛屿成员、海岸和地理范围写入统一规范化版本；同一几何由多个角色引用。

汉南由哪些街道组成、马祖归属何处、哪个固定官方面覆盖 OSM，属于项目规则，放在总体构建阶段。来源预处理只解决“如何把 OSM 表达变成完整可用要素”。

海岸来源选择本轮保持原始 OSM 岸线处理方式，不额外引入一套全球 land-polygons 下载作为默认备用源。现有两个可写同一路径的海岸方案收敛为一个正式入口。

### 6.4 固化版本的清单

每个第三类版本只需要一个总清单，包含：

- 来源版本 ID、实际快照时间或批次时间范围；
- 请求及原始响应引用；
- 规范化结果路径、哈希和覆盖范围；
- 采用的预处理实现指纹及依赖；
- 获取失败、来源缺失、未闭合海岸等结构化状态。

不再同时维护 `python-download-report`、逐省 report、`applied`、`coverage` 四套可互相矛盾的统计。面向人的摘要和日志从同一份结构化结果生成。

## 7. 离线总体构建与特殊处理

构建的输入必须完全由 `registry.json` 和选定的第三类清单确定；正常构建禁止网络请求，也不按“哪个临时缓存碰巧存在”改变结果。

按依赖顺序执行：

```text
人工 Region / Item / Place / Relation
            +
当前 OSM 规范化来源版本
            +
固定资产 + 人工绑定 + 人工规则
            ↓
按稳定身份连接来源要素
            ↓
拼接下级面、局部替换、差集、岛屿/管理区划转
            ↓
按规则进行陆地裁剪、父级汇总与接缝处理
            ↓
生成基础行政面、各开关变体、独立线要素
            ↓
生成前端目录、有效显示关系、空间匹配数据、地图资产
```

规则顺序来自显式依赖，不采用“后运行的脚本覆盖前面结果”的隐含优先级。固定输入仍可参与与动态输入的运算；“固定”指正式输入不重新获取和转换，不代表整个最终地区面永远不变。

### 7.1 现有特殊处理的去向

| 当前处理 | 新归属及执行方式 |
| --- | --- |
| DataV GCJ-02 转 WGS84 | 一次性迁移，完成后删除专用转换链 |
| 白云面替换、达茂旗洞面替换 | 固定白云资产 + 构建差集规则，保留动态达茂旗外轮廓 |
| 天地图 BIN 解码、南海线抽取 | 一次性迁移，固定最终局部几何/线；以后不解码 |
| 汉南/蔡甸、文登/环翠拼接 | 最新 OSM 下级要素 + 人工成员清单 + 组装规则 |
| 苏州工业园区及深汕 | 最新 OSM 要素 + 管理区身份 + 对应开关投影 |
| 呼中/新林、加格达奇、松岭 | 正式绑定 + 管理/名义归属规则 + 父级调整 |
| 唐古拉及相关邻县 | 最新相关 OSM 关系、固定名义局部几何及人工规则共同组装；保留要求的名义虚线 |
| 台湾/福建有关岛屿、南海诸岛 | 当前 OSM 陆地和成员 + 人工地理范围/归属规则，不按控制方改来源 |
| 黑瞎子岛、已采用的中印/中不局部修订 | 固定局部官方几何 + 确认窗口；窗口外继续采用最新 OSM |
| 历史面移除、匿名旧面排除 | 根据 Region 和绑定生成时自然排除，无需再维护一次性的删除脚本 |
| 威海县面到父级补齐 | 收敛进声明的父级汇总规则，不再做发布后的额外补丁 |
| 国界线及南海线 | 国界从当前组装结果派生；南海线直接读取固定资产；语义分开 |
| 已发布全区覆写保护 | 删除整区保护机制，改用上述局部来源与规则 |

不能从旧全区覆写几何可靠拆出的局部处理，不凭差集猜出规则。将其列为具名迁移阻塞项；在该项正式来源和作用范围确定前，不删除其唯一现存数据。现有资料不足的问题不会靠架构改造自动补齐。

### 7.2 边界选项的结构

- 开关定义、默认值、受影响对象、显示合并目标、归属变化和线样式统一在人工规则中维护，前端设置面板由此生成。
- 基础行政树、管理关系和显示投影分开。开关改变 `displayParent`、几何与交互对象，不修改源身份或静默转写记录。
- 对有关联的开关按依赖组生成变体；不生成八个开关的全国笛卡尔积。
- 相同几何在构建输出中存一次，由变体引用；按规则组拆包，前端按需加载。组数量从 manifest 读取，删除 `boundaryOptionGroups = 5` 等硬编码。
- 渲染、导入空间命中和导出都消费同一套有效边界/变体引用，不分别再实现归属判断。
- 一个源面需要在市、县两层展示时，通过 `displayLevels` 引用；维护源和组装几何不重复保存同一坐标。

## 8. 直接替换前端与 API 数据契约

维护层保持上述清晰对象；发布层只做面向访问方式的组织，不再保存另一套人工真相。

建议的发布包包含：

```text
manifest.json
  schemaVersion、buildId、inputFingerprint、OSM sourceVersion
  资源路径、内容哈希、规则组与可用层级
catalog/
  regions.json.gz
  categories.json.gz
  items/<category>.json.gz
  places/<shard>.json.gz
  relations.json.gz
  sources.json.gz
boundaries/
  base/                              # 空间匹配和几何消费用分片
  options/<group>.json.gz             # 变体引用及对应几何
maps/
  按层级/省份的降级与导出几何
tiles/
  当前内容指纹对应的 PMTiles
```

不要求前端逐个读取人工源文件。构建把人工分片合并成适度大小的访问包：首屏先读政区和类别，点位页再读所需类别/地点，地图按当前范围和层级读取资源。第一阶段保留现有 `geojson-vt` 和 PMTiles 写入实现，调整输入与 manifest；本次不同时更换地图引擎、瓦片格式或技术栈。

需要直接替换的消费逻辑：

- `CatalogIndex`：按 Region、Item、Place、Relation 建立索引；停止在 getter 中拼装另一套数据树或用 alias 改写实体身份。
- `HandbookSession`：政区状态以 Region ID、条目到访以 Item ID 保存；显式消费组成关系与显示投影。
- `PointsPage`、地图场景和记录列表：从 Item → Place → Location 读取位置，按结构化位置角色展示；取消中国机场对世界目录的运行时坐标借用。
- `visitedMapMarkers`：合并到统一的点位数据选择器，通过图层条件选择已访对象，不再单独加载研究跨表文件。
- 特殊边界设置：直接读取发布规则组元数据，不在 TypeScript 与 Python 中各写一份选项定义。
- 空间匹配 Worker、PNG 导出、MapLibre/Canvas：读取同一组装结果的相应派生格式，停止各自修补源几何。
- API 目录接口：与前端读取同一发布包，采用同一对象字段；不再读取旧 `data/catalog/catalog.json` 作为特殊入口。
- 备份、Excel、JSON 及地区清单：直接采用新身份和新结构；本轮不提供旧文件升级器、兼容版本白名单或长期双字段。

完整旧到访存档不在本次方案阶段迁移或清理。实际契约切换时按新开发格式处理，不自动删除用户已有备份和浏览器数据库。

## 9. 缓存、版本和命令入口

### 9.1 只在真正变化的环节重算

分别计算内容指纹：

1. OSM 预处理：由原始输入与预处理实现决定。
2. 行政面组装：由来源要素、固定资产、绑定与几何规则决定。
3. 目录发布：由 Region、Item、Place、Relation 和必要显示元数据决定。
4. 瓦片/降级图：由最终几何、渲染属性与生成参数决定。

改一条博物馆说明不应重下 OSM 或重做边界；修改一个固定边界只重做相关几何；修改其他国家目录不应使全部中国瓦片失效。第一阶段可以按中国数据集及规则组缓存，不为追求极细增量建立复杂的全国对象级调度系统。

第三类 manifest 记录来源更新版本；发布 manifest 记录输入组合和内容指纹。第一、二类由普通文件编辑及现有 Git/数据分发机制维护，不另开“人工数据 202610xx 版本树”。

### 9.2 收敛为少量明确命令

以下为拟议命令，方案阶段尚未实现：

| 命令 | 行为 |
| --- | --- |
| `data:fetch --scope china --source osm` | 获取缺少的原始请求并留档；允许断点续传；只操作第三类 |
| `data:prepare --scope china --source osm` | 对选定原始快照离线规范化，固化来源版本 |
| `data:update --scope china` | 顺序编排 fetch → prepare → build；整次更新成功后才切换当前正式输入与发布清单 |
| `data:build --scope china` | 读取已选定的三类正式数据，离线组装并生成发布包 |
| `data:clean --scope china` | 按清单清理中国临时及无引用派生物，排除正式输入与 OSM 原始留档 |
| `data:pack` / `data:sync` | 按 registry/manifest 打包与同步，不改变来源语义 |

`prepare:web` 可成为发布资产生成的薄入口，不再负责检查旧政策报告并夹带来源特定修补。日常启动直接使用当前成功发布包，缺包时提示执行离线构建；不能通过启动前端自动更新网络数据。

每次构建写独立 staging 目录，完成后最后发布一个入口 manifest；失败或中断时仍指向上次可用结果。Windows 正在读取的旧资产可延后清理，不为了强行删除而破坏当前地图。

## 10. 实施顺序与每阶段产物

### 阶段 A：建立唯一正式输入

1. 创建 registry、来源登记及对象 Schema。
2. 将当前中国 Region、14 类目录、点位、组成关系和榜单拆为人工维护文件。
3. 将机场已确认的位置结果固化进正式 Place，记录未确认位置及旧来源缺项。
4. 提取第二类固定资产，尤其是白云面、南海段线、天地图现用局部几何、港澳保留分区。
5. 导出当前已确认的外部 ID 绑定，整理特殊规则。

产物：人可以独立维护的正式源；此时不删除任何尚未转移的唯一几何。

### 阶段 B：统一 OSM 来源版本

1. 将现有原始响应合并到内容寻址留档，旧多路径数据只保留一个原始副本。
2. 从同一对象池整理行政关系、特殊下级关系、群岛与海岸。
3. 以现有资料导入组合来源版本；标明各批次日期和缺项。
4. 将获取、缺件补充、规范化和版本清单收敛到统一入口。

产物：不依赖旧运行几何、临时研究目录的第三类正式输入。首次真实联网更新是单独操作，不是迁移能否完成的前置要求。

### 阶段 C：替换总体组装和边界规则

1. 删除“从上一次发布文件继续打补丁”的依赖。
2. 用确认绑定连接来源；重放有限类型的局部规则。
3. 生成行政面、显示关系、变体和独立线。
4. 用显式依赖确保每个操作只执行一次；将相关状态写入一个构建清单。

产物：仅靠 registry 中正式输入就能离线生成的中国发布包。

### 阶段 D：一次性切换消费契约

1. 替换 contracts、catalog、domain 及个人记录的新结构。
2. 修改区域页、点位页、列表、成就、导入导出与 API。
3. 保留现有地图技术栈，调整瓦片、变体、降级图和空间匹配输入。
4. 删除旧 `recordId` 间接展示结构、兼容映射和运行时研究文件导入。

产物：前端/API 只消费新发布结构，不存在两套来源和两条读取链。

### 阶段 E：清理与更新维护说明

1. 将旧路径逐项标记为已迁入、由何物替代、是否仍有引用。
2. 清理无引用的旧数据、转换脚本、草稿、重复报告和已废弃的打包清单。
3. 更新数据下载/来源/打包说明，使它们指向新的唯一入口。

产物：当前维护文件、最新成功来源处理结果、最新成功发布结果及去重 OSM 原始留档。

## 11. 具体清理范围

以下是实施后的清理目标，不是本次已经执行的删除。清理依据是新 registry 与发布 manifest 的引用关系；不依赖全盘文件名通配删除。

| 旧位置或内容 | 处理 |
| --- | --- |
| `data/catalog/catalog.json` 中的中国人工内容 | 迁入 manual；旧聚合文件退出维护源，切换完成后移除中国旧格式 |
| `data/catalog/china.geo.json` | 由新组装结果取代，删除旧运行格式副本 |
| `data/catalog/china-boundary-options.json` | 改为按规则组发布的派生包，删除旧整包 |
| `data/boundaries/china-osm/*.geojson` | 作为迁移输入使用后，由统一规范化来源版本取代；不在多个目录保留相同来源面 |
| `china-osm/raw`、`data/tmp/osm-china*` 中的原始响应 | 未改写原件迁入 archive 去重；删除旧路径副本，原始输入仍留档 |
| `china-policy/sources` 内的 OSM 数据 | 同样迁入 archive/remote，删除重复拷贝 |
| `china-policy/sources` 内的非 OSM BIN、SHP、网页及解码副本 | 所需结果固化后清理原件/中间件；来源事实迁入 sources 和 asset 元数据 |
| `reviewed-patches.json`、`published-overrides.json` | 所有现用处理拆为固定资产及规则后删除，停止整区冻结 |
| `references/pre-coastal-base`、`admin-options-base`、`policy-before-*` 等旧整图备份 | 可由新正式输入重建且无唯一数据残留后删除，不长期保存多代处理结果 |
| `land-mask.geojson`、`osm-land-outlines.geojson` | 移入当前第三类处理结果或派生产物，只保留一个正式来源路径 |
| 大量 `*queries*.json`、`.overpass`、`*downloads*.json` | 当前有效需求合并到 request-plan；纯历史批次清理 |
| `applied`、逐省 report、coverage 及重复 audit | 必要事实迁入统一来源/构建清单，删除已替代报告 |
| `china-airport-map-associations.json` | 已确认位置与限制迁入 manual/places 和 pending 后删除旧关联包与其构建脚本 |
| `china-heritage-map-association-audit.json`、祠堂研究材料 | 必要缺项、来源和现用成就事实迁入正式对象；无继续用途的大型重复报告清理 |
| 临时 review PNG、旧截图、`data/generated` 的旧 UI 源码副本 | 确认无其他用途和引用的中国相关产物后清理 |
| 旧中国下载/转换/政策/修补脚本 | 公共函数保留整合；已替代一次性脚本删除，不保留两个可写正式数据的入口 |
| 旧中国 PMTiles、PBF、简化图和发行包缓存 | 成功切换新 manifest 后清理无引用文件；保留当前正在使用资源至可释放 |
| 非中国正式数据、研究文件、原始输入 | 本轮不清理；删除共享脚本前确认并迁出其非中国职责 |

现有数据包混合中国与其他国家。迁移应调整打包清单，使中国的 manual、fixed、remote、runtime 各自有明确角色；旧全量同步包不能继续反向覆盖新中国目录。其他国家可暂时由原输出装配入口接入，等后续逐国整理，不为它们建立一套新的长期兼容架构。

## 12. 完成条件与工作边界

完成后应能直接回答：

- 改一个文保名称：只编辑一个人工对象，重新生成目录即可。
- 更新 OSM：一次获取包含全部有效特殊依赖；不会重新获取 DataV 或天地图。
- 查看白云、汉南、唐古拉或南海段线：由 registry、来源绑定、资产和规则可直接追到最终对象。
- 更改边界归属规则：只修改相应人工规则，离线构建即可，无需重抓已有来源。
- 删除整个中国派生目录：仅凭正式输入就能重建，不依赖旧运行文件、历史草稿或临时研究缓存。
- 点位是否可画、是场所点还是代表点：由统一字段判定，不读取名称前缀或解释字符串。
- 一项规则失败：明确指出缺少的来源对象或冲突输入；本次候选结果不替换当前可用发布包。

实现时仅保留构建必需的结构、引用、完整性和规则冲突约束，不为本次整理另开全国地理核验、资料真实性调查或浏览器测试工程。现有条目数量和来源缺项用于迁移对照，不永久硬编码为未来不可变化的总数。

本次交付仅为这份改造方案。实际实施按“正式输入 → OSM 版本 → 总体组装 → 消费契约 → 清理”的顺序推进，允许直接替换旧设计，不承担旧格式兼容工作。
