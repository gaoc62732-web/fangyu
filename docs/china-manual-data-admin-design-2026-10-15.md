# 中国区划与点位数据管理页开发方案

状态：方案修订稿，2026-10-17

本文件是产品体验、数据边界和实施方案基线，当前实现按阶段落地。首版先覆盖中国点位资料维护和点位位置地图编辑；区划资料与边界顶点编辑继续按本文约束逐步建设。方案只面向当前中国区划点卯与点位点卯使用的数据。

## 1. 修订结论

旧稿以数据集、字段 schema 和通用表格为主入口，要求管理员先理解数据存储结构，再逐字段编辑。这个方向不符合管理者无需了解后端结构即可完整维护资料的目标。本稿改为以管理员熟悉的业务对象和任务组织界面：

- 以“区划资料”和“点位资料”作为两个主要工作区。先搜索、浏览并选中一个区划或点位，再在该对象上下文中查看和编辑资料。
- 区划工作区包括区划基本信息、上下级关系、公开详情、来源和该区划的实际地图边界。
- 点位工作区覆盖点位点卯可查看的全部条目，以及尚无坐标、坐标无效、待补或当前不能绘制的记录。地图上没有标记不能成为管理列表漏掉记录的理由。
- 地理信息在底图上编辑。地图、图层、坐标输入、边界工具、校验结果和保存预览共同构成编辑基础设施；地图是编辑环境，不是仅供装饰的预览图。
- 界面用中文业务名称和按语义分组的控件呈现资料。后端字段名、文件名和 JSON 结构不作为主要导航或默认表单。
- 页面有独立布局和独立路由。普通前端导航不放管理入口；管理员通过手动输入路由进入。路由隐藏只满足入口独立要求，不能替代后端权限校验。

字段 schema、服务端校验、文件注册表、版本控制和共享边拓扑仍是必要的实现措施，但应服务于上述对象工作流，而不是成为管理员必须理解的产品界面。

## 2. 目标与范围

第一版目标：

1. 管理员能按区划层级、名称、代码、别名及点位类别检索对象，并能从地图或列表进入详情。
2. 对所选对象可读、可编辑其在现有页面展示的信息及其后端已维护的相关资料。原始字段中尚未进入普通页面的有效信息也要有明确查看和维护入口。
3. 点位完整清单从正式目录和位置待补资料建立，而不是从已有地图标记建立；列表说明每条记录为何有坐标、无坐标或不能绘制。
4. 可以在地图底图上添加、移动和校准点位位置，也可以可视化编辑区划边界，并在保存前看到数据影响和校验反馈。
5. 保存到受控的正式人工数据源，首版先保证并发检查、原子写入、跨文件事务和失败回滚；持久审计、备份和发布后的前端地图资源切换按后续阶段建设。

第一版不扩展到中国以外的数据管理，也不把成就定义、非中国目录或所有后端数据集改造成通用 CRUD 控制台。与区划和点位资料有关的类别、来源、称号、组成地点、对象关系和待补记录，在需要时从区划或点位工作流内编辑。用户个人的点卯/旅行记录不属于人工目录资料，不由此管理页修改。

管理页面路径约定为：

    /admin/china/points

首版点位页在工作区内选择对象，后续可增加 `/admin/china/regions/:regionId` 和带对象 ID 的深链接。应用使用 hash 路由时，管理员可手动打开对应的站点地址及 hash 路径。普通页面的导航、页脚、帮助页和业务按钮均不出现进入管理页的链接。
管理页面可以有自己的工作区导航和返回普通页面的显式出口，但不复用普通站点的模块导航作为入口。

## 3. 现状与需要遵守的数据事实

- 前端使用 Vue 3、Pinia 和 Vue Router；当前路由在 apps/web/src/app/router.ts，普通模块导航在 apps/web/src/components/AppHeader.vue。
- 区划资料页面为 apps/web/src/pages/CatalogPage.vue。当前区划资料栏展示名称、代码、称号、说明/公告及按区划关联的目录点位；其中有些内容由目录索引、关系或派生逻辑组合，不一定存放在同一个区划 JSON 对象中。当前区域概况文案没有实际数据来源，不能将空占位误当成已存在的可编辑字段。
- 点位资料页面为 apps/web/src/pages/PointsPage.vue。资料栏包含名称、类别、到访状态、所在区划、认定类别、编号、年份、遗产类型、组成地点、所属总项目、关联身份、简介、备注以及坐标缺失提示等。类别与条目资料可能由多份源数据装配；需要区分直接存储字段和派生展示内容。
- 数据契约在 packages/contracts/src/catalog.ts。Region 与 CatalogEntry 展示类型不是人工源 JSON 的完整 schema；条目类别专属和来源专属数据可位于 attributes 或其它被装配的数据结构中。
- 人工维护源目录为 data/manual/china/，包含 regions、items、places、components、relations、pending、sources、recognitions、rules 等资料。主目录装配逻辑在 scripts/lib/assemble-manual-china.mjs。实现前需要建立字段到源数据及反向写回的可追溯映射。
- 当前普通点位图层按可绘制坐标筛选条目。点位资料列表可以显示暂无坐标的条目，但单凭地图图层、当前可见视野、聚合物或普通页面已加载的数据不足以成为完整管理清单。
- 点位管理使用独立的本机 JSON API 入口 `apps/api/src/admin-main.ts`，不加载 Better Auth、数据库连接或普通业务 API 模块；服务只绑定 `127.0.0.1`，管理写入由服务端直接更新 `data/manual/china/` 中的正式 JSON 源。浏览器不直接访问磁盘，也不通过下载文件完成保存。API 按源文件版本刷新读取缓存，因此手工编辑源 JSON 后重新载入可读取最新内容。
- MapLibre 和现有地图场景可作为地图交互的技术基础，但管理编辑需要独立的底图、几何加载、绘制草稿、校验、保存及冲突反馈能力。普通点卯地图的展示交互不能直接当作完整 GIS 编辑器。
- 中国共享边迁移产物已经位于 data/manual/china/boundaries/，但其 README 明确记录该目录处于部分迁移阶段，尚未接入前端发布构建；其中未完成拓扑、migration-pending、pending-* 等资料不能视为当前有效的可编辑区划边界。详见[中国边界共享边与版本更新扩展设计](china-boundary-shared-edge-design-2026-10-15.md)及 data/manual/china/boundaries/README.md。

## 4. 面向管理者的工作区

管理页打开后直接进入中国资料工作区，不做产品介绍页。主界面提供“区划”和“点位”两个业务入口。当前所选对象、搜索、筛选条件、地图视野和未保存状态应能随路由恢复，复制对象地址也可重新打开同一资料。

### 4.1 区划资料

区划列表以层级树、名称搜索和代码/别名搜索为核心，支持按省、市、县等层级筛选。列表行显示便于辨认的信息和资料状态，例如上下级路径、边界是否可用、资料是否有待复核。管理员不需要从文件名或 ID 前缀猜区划归属。

选择区划后进入资料工作区：

- 地图显示目标区划、相邻区划、父级背景和当前有效边界；可以在资料面板与边界编辑视图间切换。
- 资料按“名称与识别信息”“所属关系”“公开说明”“称号与别名”“来源与更新时间”“其它已维护信息”等语义组展示。字段按当前有效源数据动态补全；不属于目标区划的统计量和用户点卯状态应标成派生或只读信息。
- 边界状态明确显示当前来源、适用层级、最后验证情况、已有人工覆盖及其冲突。数据尚未完成拓扑迁移时，页面可以查看可用的当前几何和迁移状态，但不得开放会写入不完整拓扑的编辑保存操作。
- 从区划详情可跳转到关联点位。维护父子关系或称号等关联资料时显示对端名称和上下级路径，避免让管理员只看到难懂的外键 ID。

### 4.2 点位资料

点位目录按类别组织，支持按名称、别名、代码和关联区划搜索，并可筛选坐标状态、资料完整度、来源状态、组成关系和待复核状态。服务端查询正式源清单，不受地图缩放、点位聚合、ordinaryPointEligible、当前类别或普通目录分页的影响。

至少区分以下记录状态：

- 有有效坐标且可在地图绘制。
- 无坐标，但可以在地图中创建位置。
- 坐标结构存在但超出经纬范围、格式错误或与坐标来源冲突。
- 有位置待补记录，尚未匹配到正式点位或实体地点。
- 有点位资料但因明确规则不显示为普通点位。
- 仅有候选/待处理资料，尚未形成普通页面可访问的点位记录。

选中点位后提供地图和完整资料面板。地图有坐标时定位到位置；没有坐标时以明确关联区划为参考范围，并显示“尚无坐标”而不虚构地图标记。没有关联区划的记录仍可通过全国地图、坐标搜索或手动输入继续处理。

资料面板按使用含义分组展示名称、类别身份、代码/认定信息、关联区划、简介/备注、位置及来源、组成地点、所属总项目、同地其它身份、相关记录和维护状态。已有点位详情显示但未进入普通目录摘要的有效字段也必须可见。类别专属字段使用对应业务控件；无法映射的历史字段保留并显示在“其它资料”组，不能因为编辑常用字段而丢弃。

### 4.3 存储信息的可读性

管理员界面以中文标签和自然语言说明呈现信息。稳定 ID、来源记录 ID、文件修订号等技术标识可以复制和搜索，但放在折叠的“维护信息”区域。来源引用显示来源名称、链接、授权及引用目的；区划关系显示完整路径；数组和嵌套资料转换为可读清单。

表单不是数据库字段浏览器。常用字段用文本框、数值框、开关、选择器、地点关系选择器和地图控件编辑。未知字段和低频复杂数据提供保留原值的高级查看/编辑入口，并在普通字段保存时确保完整往返。任何字段都不能因 UI schema 暂未认识而被删除或重置。

当前页面显示的派生值应标明其来源对象或组成关系。默认不允许直接编辑派生展示值；页面应提供编辑实际来源对象或关系的入口。个人到访状态只用于说明普通页面效果，管理者不能在这里替用户修改到访记录。

首版点位页已经按这一原则提供目录分页、位置状态筛选、语义字段、高级 JSON 往返、政区搜索和位置备注；组成地点关系暂以只读数量和删除保护呈现，避免在尚未完成关系事务编辑前破坏 `components.json` 与 `relations.json` 的一致性。

## 5. 地理可视化编辑基础设施

区划边界和点位位置共用一套管理地图运行环境，但采用不同的编辑工具和保存命令。它建立在 MapLibre 与现有地图数据服务之上，并以独立组件和数据 API 对普通地图交互解耦。

### 5.1 底图与图层

管理地图需要提供可读、稳定且有出处的背景信息。实施时先盘点现有静态边界、地图瓦片、PMTiles、简化图形和可用底图资源，再确定首版底图组合；不得默认依赖未配置密钥、无授权或无法离线访问的在线底图。底图来源、授权和必要署名在地图内可查。

编辑视图至少能切换显示层级并控制以下图层：

- 背景底图及其来源标记。
- 当前已发布/当前有效的行政区面和边界，仅作为对照。
- 来源边界或外部来源几何，只读并标明来源、版本和状态。
- 已生效的本地边界编辑或固定边界。
- 当前管理员的未保存草稿。
- 邻接区划、目标区划和涉及变更的受影响区域。
- 点位位置、参考坐标、坐标精度范围和编辑候选。

各来源必须用清晰图例、线型/颜色及可访问的名称区分。编辑草稿不能覆盖底图，选中要素后显示来源和版本。无来源、加载失败、非目标层级和拓扑未完成应有明确状态，不以空白地图掩盖错误。

### 5.2 地理数据服务和地图视图模型

管理端地图 API 提供按需加载的编辑上下文，而非每次下载全国全分辨率几何。区划编辑上下文至少包含目标及邻接区划的当前有效面、来源几何/版本、人工覆盖、允许的编辑范围、影响对象和各图层 revision。点位编辑上下文包含位置、定位证据、关联区划、参考点及上下文边界。

全国概览和搜索使用简化几何、瓦片或空间索引；放大到选中区划后按对象/视口读取编辑级几何。客户端可缓存可见背景数据，但编辑草稿和保存 revision 单独管理。几何加载时显示数据版本、坐标数量或精度提示，并避免大 MultiPolygon 阻塞界面。

地图编辑层应与前端展示层分开：编辑服务将人工源、第三类来源、当前发布结果和草稿组合为清楚的只读/可编辑视图模型；保存命令再把用户意图写回对应规范源。前端不得尝试从发布后的合并 GeoJSON 反推该改写哪个数据文件。

### 5.3 坐标基准与点位位置编辑

现有人工地点坐标约定为 WGS84，经度在前、纬度在后。管理 API 统一传输和保存这一约定，并明确每种底图的坐标基准。底图需要其它坐标系时，通过集中、可测试的地图投影适配器在显示时转换；不得混用 WGS84、GCJ-02 等坐标并写回错误值。页面同时显示经纬度和格式化地址/所在区划提示，地址提示不得替代用户确认。

管理员可以点击地图新增坐标、拖动已有点、直接输入经纬度、清除候选位置、撤销/重做，并查看变更前后位置。每次定位同时维护可读的来源、定位方法、精度/位置类型、核查时间、备注和入口是否已核实等实际适用信息。参考坐标、官方报告坐标与普通目的地点位需要分别显示，避免把参考值误当作游客入口。

位置缺失表示尚未定位。不得由区划中心、名称搜索结果、地图点击背景或反向地理编码自动生成正式坐标。完成 pending 项时，先展示匹配到的正式点位/实体地点及将要写入的字段；涉及点位、Place、pending 多个文件时一次性提交或全部回滚。

### 5.4 区划边界编辑

界面以“编辑这个区划的边界”作为入口，而不是要求管理员先理解 arc、ring、profile、override 等内部模型。底层边界保存采用共享边技术：县界只维护一份共享几何，邻接区划按方向引用；固定来源线和不参与面闭合的独立线也需明确区分。该数据模型和版本更新条件遵循[边界共享边与版本更新扩展设计](china-boundary-shared-edge-design-2026-10-15.md)。

地图编辑工具需要支持选择区段、拖动顶点、插入/删除顶点、描绘/编辑环、管理 MultiPolygon 分片与内环、撤销/重做、前后叠图和保存前预览。对于共享边编辑，视图同步高亮两侧区划并说明两侧都会受影响；一条边只保存一次，不能生成相邻区划不一致的两份独立真相。

每份边界草稿保存目标区划、涉及边界层级、来源版本、原因、来源引用和基础 revision。校验检查经纬范围、坐标有限性、闭环、环方向/嵌套、空几何、自相交、跨越非预期邻区、有效引用、共享边方向和可能受影响的上下级拓扑。校验在地图上定位到具体区域、环和顶点，并提供错误与警告的区别。除非明确执行并预览修复，系统不得自动改写或丢弃用户几何。

文档中的 10 米端点接续政策只用于共享边方案所述的来源版本更新候选匹配，并需逐点呈现新旧坐标和距离；它不是普通编辑时的静默吸附规则。人工编辑需要的吸附必须由管理员显式启用、预览并确认。

由于现有共享边迁移尚未完成且未接入发布，边界编辑开发必须先提供来源完整性/可编辑性状态和只读预览。正式写入某区划边界之前，服务端必须确认对应层级拓扑、来源边匹配、共享引用及构建链路处于可用状态。未完成的边界只能进入单独草稿或迁移队列，不能冒充正式修改，也不能阻塞当前可用边界的普通显示。

## 6. 数据读写与发布设计

### 6.1 对象视图与正式来源

建立区划资料和点位资料的业务视图模型。视图模型可聚合 regions、items、places、components、relations、sources、recognitions、pending 及边界服务返回的信息；各可编辑字段记录其正式来源和写回命令。管理员按业务对象操作，服务端根据注册好的来源映射写入固定文件。

正式人工源继续作为数据真相，不在管理页面另造一份无法同步的数据库副本。普通目录装配结果、压缩目录、地图 GeoJSON、瓦片与构建缓存仍是派生产物。浏览器只能提交稳定对象 ID 和已知编辑命令，不能提交任意服务器路径、文件名或客户端自定义 schema。

第一版范围内的主要来源包括：

| 业务对象        | 主要来源                                               | 管理者入口                                   |
| --------------- | ------------------------------------------------------ | -------------------------------------------- |
| 区划基本资料    | data/manual/china/regions.json、regions/*.json         | 区划树和区划详情                             |
| 点位目录资料    | data/manual/china/categories.json、items/*.json        | 类别目录和点位详情                           |
| 实体位置及组成  | places.json、components.json、relations.json           | 点位详情中的位置、组成和关联区域             |
| 缺失/待核对位置 | pending/locations.json、pending/airport-locations.json | 点位工作区的待处理筛选与队列                 |
| 来源和认定称号  | sources.json、recognitions.json 及相关引用             | 资料卡中的来源和称号编辑器                   |
| 边界维护资料    | 当前人工边界规则、固定资产及已迁移的共享边源           | 区划详情的边界工作区；按数据可用状态开放编辑 |

manifest 和目录计数为派生维护信息，不开放普通业务字段编辑。类别定义在点位工作流中以业务名称呈现，不能要求管理员先进入字段 schema 页面。

### 6.2 保存、冲突和删除

打开对象和地理上下文时返回对象/文件 revision。保存时要求基础 revision 未变化；冲突时返回服务器当前资料和字段差异，管理员重新载入或手动合并，不能静默覆盖。

写操作先在服务端执行 schema、引用和地理校验，再锁定涉及源文件并重读当前值。单对象写入使用原子替换；点位坐标、Place 链接和 pending 队列等多文件改动作为事务执行，失败时全部恢复。首版已实现文件锁、修订号校验、原子替换和失败回滚；持久备份及精简审计（操作者、时间、对象、字段/命令、前后 revision 和原因）在正式扩大写入范围前补齐。

区划、类别、来源、地点和关系等被引用对象不可静默级联删除。删除或解除关系前，显示会受影响的实际对象及其名称和路径；确认后按事务写入。安全地删除无法满足校验时应阻止操作并说明需先处理哪些引用。

### 6.3 预览与发布

保存表示正式人工源已更新。动态 API 缓存可在保存后失效；静态目录、边界 GeoJSON、瓦片或 PMTiles 是否更新取决于构建流程，界面必须分别显示“已保存”和“已发布”状态。

边界及地图资源在 staging 中构建和验证，成功后原子切换当前发布版本。构建失败保留上一个可用版本，并展示明确错误、受影响区划及重试操作。对于仍未完成共享边迁移的对象，显示迁移状态，不误报为已经发布的新边界。

## 7. 管理 API 与权限

管理 API 位于现有 /api/v1 前缀内。建议使用业务命令而非完全通用的数据表 CRUD，主要能力包括：

| 能力               | 目的                                                         |
| ------------------ | ------------------------------------------------------------ |
| 管理能力与数据状态 | 确认当前用户权限、区划/点位资料版本和发布状态                |
| 区划目录与详情     | 搜索、树形浏览、读取完整资料和关联摘要                       |
| 点位目录与详情     | 对正式源及 pending 做服务端搜索分页；返回无坐标/不可绘制原因 |
| 区划地图上下文     | 按需读取有效几何、来源版本、邻区、草稿和可编辑性状态         |
| 点位位置上下文     | 返回坐标、参考值、证据、关联区划及地图显示所需边界           |
| 资料更新命令       | 对允许编辑的业务字段执行有 revision 的修改                   |
| 地理草稿与验证     | 创建/恢复草稿、执行拓扑和坐标校验、查看前后预览              |
| 保存及发布任务     | 原子保存正式来源，构建候选地图资源并查询状态                 |

列表由服务端建立轻量索引并分页。点位索引需要包括完整目录记录与 pending 关联状态；查询不得以是否有坐标、是否在视口内或是否当前可见作为筛选前提。大型 GeoJSON 按区划、边界层级或视口懒加载，并使用明确的请求上限。

当前点位管理 API 是仅供本机使用的 JSON 管理服务，不要求数据库、账号或管理员白名单；服务端固定监听 `127.0.0.1`，并拒绝非回环请求。普通站点不提供入口，手动访问管理路由仍需要本机开发服务和点位 API 正在运行。浏览器只发送对象 ID 和业务编辑命令，服务端将其映射到固定 JSON 源文件；不得接受客户端路径，也不以浏览器下载/上传文件作为保存机制。该本机访问边界不适用于公网部署。

## 8. 前端与后端模块建议

管理前端使用独立 AdminShell 和按需载入页面，不展示普通 AppHeader。可复用领域类型、地图绘制基础和经过评估的 MapLibre 生命周期，但不复用普通地图的只读交互作为编辑逻辑。

建议的前端能力：

- 中国资料工作区、区划目录/详情、点位目录/详情。
- 语义字段组、关系选择器、来源查看器和未映射字段保留区。
- 独立 GIS 编辑场景，分离底图、只读来源、有效结果、草稿和冲突图层。
- 点位位置编辑器、区划边界工具、校验/变更预览、撤销与恢复。
- 带 revision 的 API 客户端、服务端权限状态、加载/失败/离线状态和未保存提醒。

建议的后端能力：

- 本机访问守卫：限制点位 JSON 管理 API 只接受回环请求。
- ChinaAdminReadModel：服务端搜索索引、业务对象聚合、字段来源映射及状态计算。
- ChinaAdminWriteService：固定源注册表、字段白名单、引用校验、revision、写锁、事务、备份和审计。
- GeoDataService：底图与来源清单、区划/视口几何读取、坐标投影适配、空间索引、边界草稿和拓扑验证。
- PublishService：候选目录与地图资源构建、验证、版本切换和状态查询。

任何保存服务均不能通过将客户端传入的路径拼接到 data/manual/china 来决定写入目标。先根据业务对象和允许命令查固定注册表，再对最终路径做范围校验。

## 9. 实施阶段

### 阶段 A：数据映射与 GIS 底座

盘点区划资料栏和点位资料栏的每个显示值、其来源对象、派生方式和可编辑规则；抽查正式源、装配后目录、地图几何和 pending 的差异。完成管理权限、独立路由/页面壳、服务端搜索分页、revision 协议，以及 MapLibre 编辑场景的底图和分层数据契约。

### 阶段 B：点位资料和位置编辑

先接入完整点位源记录与 pending 队列，确保缺坐标、无效坐标、不可绘制和仅待处理项目都能检索。建立按类别显示的语义详情表单，完成位置来源/精度展示、地图点选与拖动、校验、冲突处理及多文件事务。

### 阶段 C：区划资料与地图浏览

建立区划树、完整资料视图、关联关系编辑和中国区划地图上下文。确保地图选择区划和列表选择区划使用同一对象状态，并提供当前有效边界、邻接关系、来源和版本的可读解释。

### 阶段 D：边界可视化编辑

先依据共享边迁移清单补全指定层级的来源拓扑、邻接关系、旧人工覆盖映射和候选发布构建链路。仅在数据状态证明编辑目标可安全写入后，逐步开放连续共享边编辑、内外环编辑、多层级影响预览、冲突队列和拓扑发布验证。未完成对象保留只读或草稿状态。

### 阶段 E：覆盖和发布验证

以实际区划、点位和无坐标记录演练查找、编辑、并发冲突、回滚和发布流程。验证普通区域点卯和点位点卯仅在成功发布后读取新目录/地图版本；完整性报告应能比较正式源、待补队列、装配结果与地图可见性。

## 10. 验收标准

1. 普通站点没有管理入口；手动输入管理路由可打开独立管理布局。非管理员直接访问管理 API 会被拒绝。
2. 区划可以通过名称/代码搜索或层级树定位，详情中可读写全部已纳入范围的业务资料；所有公开页面字段都能追溯到其来源或被标明为派生只读值。
3. 地图和清单能表示当前有效区划边界及来源状态；不完整迁移对象不会开放正式保存。
4. 点位管理清单不依赖地图 marker。每条正式条目和 pending 位置都可找到，且可筛选其无坐标、坐标异常、不可绘制或待匹配状态。
5. 点位详情覆盖普通页面所显示的资料、关系和缺失提示；类别专属及未映射的有效源字段在维护界面可见，保存常用字段不会丢失它们。
6. 地图新增/移动点位后，坐标输入和地图一致；坐标基准及来源明确，未确认位置不写入正式数据。
7. 边界图层能分别识别来源、当前结果、固定边、人工编辑和草稿；共享边变化会显示邻区影响并只保存一个共享几何真相。
8. 无效坐标、无效环、引用冲突和拓扑错误在保存前后均有可定位反馈；发生并发写入时不会覆盖他人修改。
9. pending 完成、关联和位置修改等多文件命令具备全成或全回滚语义；首版的并发冲突和失败回滚可验证，持久审计和可恢复备份列入发布前验收。
10. 页面能清楚区分已保存、构建中、已发布和发布失败。失败时普通站点仍提供上一个成功版本。

## 11. 明确不做的事

- 不把普通站点的导航增加为管理入口。
- 不要求管理者学习目录文件结构、原始 JSON schema 或共享边内部 ID 才能完成日常编辑。
- 不以当前可见地图点、用户当前地图视野或普通页面分页结果代替完整点位资料目录。
- 不把用户个人点卯状态作为中国人工数据编辑对象。
- 不把发布后的 GeoJSON、地图瓦片或目录缓存当作正式人工数据真源。
- 不静默推断位置、切换坐标基准、吸附人工边界或自动修复无法确认的拓扑。
- 不在共享边来源/拓扑不完整时，将迁移参照或候选几何作为已验证行政区边界保存发布。
- 区划完整资料工作区、边界顶点编辑、发布构建和审计备份仍属于后续阶段；首版点位工作区可以写入受控人工源，但不能把未完成的边界迁移对象开放为正式边界编辑。

## 12. 点位工作区布局修订（2026-10-17）

- 使用主页面的纸色、墨色、细边框、字体和图标；顶部仅保留紧凑标题、刷新和新建。地图铺满左侧，右侧为固定宽度的工作面板；窄屏采用上地图、下面板，两部分均保留明确的可用高度。
- 右侧目录与编辑采用两个可切换视图，避免长列表和长表单上下挤占高度。分页、编辑底部操作栏固定，内容区独立滚动；切换目录或筛选不清除当前草稿。切换点位、还原或重新载入前，若有未保存修改则确认。
- 编辑优先展示位置：经纬度、政区、位置备注和入口核实；随后为名称、别名、简介。技术 ID、场所信息和原始资料暂收进默认折叠区域，原始字段保留兼容，后续按类别逐步转成业务表单，不扩大 JSON 编辑器作为常规工作入口。
- 新建复用已有对话框；新建类别与目录筛选分开，避免创建时改变目录或丢失草稿。地图复用现有底图、瓦片和图标，保持挂载，支持点选、拖动、缩放、全图和返回当前点位。无坐标时可根据已关联政区定位地图；点选识别出的政区紧邻当前关联显示。
- 无新增常驻说明文案；加载使用骨架或图形状态，未保存使用标记，保存结果收敛到保存按钮。必要字段、操作、错误、危险操作确认与业务数据仍可显示；不得用提示替代布局与交互设计。
