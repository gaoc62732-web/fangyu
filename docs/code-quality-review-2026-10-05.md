# 代码质量审查与清理（2026-10-05）

## 判断

项目已经具备前后端分层、共享契约、领域规则和事务保存的基础，但工程约束没有跟上多轮界面替换。主要问题是旧实现退出路由后仍留在源码中，旧测试继续依赖这些实现，类型检查长期失败；少量保存和后台通信错误也被界面流程掩盖。继续增加功能之前，应保持现有质量检查可执行。

## 删除依据

从 `apps/web/src/main.ts`、`apps/api/src/main.ts` 和仓库脚本入口遍历静态导入、动态导入、包导出及 Worker 的 `new URL()` 引用，测试引用不作为保留生产代码的理由。核对路由与全仓库引用后，删除以下 13 个无入口源码文件：

- 旧工作区：`apps/web/src/app/workspace.ts`。
- 旧目录实现：`components/CatalogList.vue`、`components/EntryDetails.vue`、`features/catalog/categories.ts`、`features/catalog/client.ts`、`features/catalog/query.ts`、`workers/catalog.worker.ts`（均位于 `apps/web/src/`）。
- 旧地图与导出：`apps/web/src/components/FootprintExport.vue`、`apps/web/src/components/LegacyMapSurface.vue`、`apps/web/src/pages/LegacyMapPage.vue`、`packages/map-renderer/src/footprint.ts`。
- 旧管理页及占位类型：`apps/web/src/pages/ManagePage.vue`、`apps/web/src/features/imports/job.ts`。

同时删除仅测试旧查询引擎的 `query.test.ts`，将过时的界面、地图测试改写为当前实现的回归测试，将 Vitest 配置移至实际声明依赖的 web 包。公共目录加载只有当前支持清单、缓存和 gzip 的入口，删除另一个无调用的 `loadCatalog()`。

新增 `scripts/check-source-usage.mjs` 防止无入口源码再次累积。这是文件级引用检查，支持当前仓库的导入形式，不代替运行测试，也不声称能发现所有未调用的导出或运行时生成的引用。独立数据工具仍按独立入口处理。

## 当前验证边界

1. 浏览器实际加载耗时和视觉表现尚未测量；构建 manifest 只能证明依赖边界。地图引擎、目录共享模块和 ExcelJS 仍较大，继续优化应以实测为依据。
2. 地图生命周期与页面回归使用合成数据和模拟渲染器；生产认证、数据库并发和多用户隔离尚未进行端到端验收。
3. `.mts` 工具已纳入类型检查，JavaScript 工具的函数体仍未开启 checkJs。源码入口检查仍是文件级分析，显式导出也不等同于自动检查所有无消费者符号。
