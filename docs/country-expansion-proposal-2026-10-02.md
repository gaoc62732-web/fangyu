# 国家、遗产与球场扩展建议（仅设计）

本轮没有新增国家区划、遗产、球场或成就规则。以下依据实际代码与当前目录，不是对各国官方现行数量或资料许可的认定；官方边界及遗产来源由上层研究单独核验。

## 现有基础与改造次序

当前 `Scope`、路由、地图及部分页面将范围写为 `china/world/japan/korea`。直接复制页面会放大硬编码。建议先引入国家专题注册表，描述专题 ID、上级世界国家 ID、默认层级、区划层级名称、资源索引、类别和成就入口，再逐个接入国家。

`CatalogEntry` 已有 `categoryId`、经纬度、别名、`subitems`、`recordId`、`topicRegions`。同一世界遗产或机场应保留同一个实体和记录 ID，通过 `topicRegions` 增加专题归属，避免世界页和国家页重复计数。国家专题一级及下级区划需稳定 ID、行政代码、父级、层级、别名、现行/历史状态；几何引用同一个 regionId。数据源、许可、适用日期、版本与替换映射应进入构建清单。

新国家成就宜使用声明式目标集合与条件（地区/地点、任意/全部/最低数量、分级门槛），复用现有计算和 Worker 呈现；不要把海外城市/郡数直接计入中国县区数量称号或卯分。国家入口是否复用九系列布局可以后续评审。

## 英国“郡”

不要将英格兰礼仪郡、行政郡以及苏格兰、威尔士、北爱尔兰的行政层级混成一种可相加的“郡”。先确定用户希望记录的口径，再让注册表提供不同分区体系；实体保留体系 ID 与有效日期，同一地点可映射多个体系。作为行政旅行记录时，建议先国家组成部分再接各自明确的现行行政单元；礼仪/传统郡可另设专题。

## 乌兹别克斯坦、越南国家级遗产

国家级遗产应作为各自国家定义的独立类别，与世界遗产区分。需要官方名录编号、原文名、中文显示名、批准/变更日期、保护级别、坐标、来源链接、许可/使用条件；不要通过名称包含“国家级”推断身份。若同一实体既属世遗又属国家名录，以实体 ID 关联多个认定，不产生两次到访记录。

两国分级体系、项目口径和名录是否有可用坐标需要官方核验；批量导入前应抽样检查边界、重复、撤销/升降级及历史名称。尚无坐标的项目可在列表记录，但不能伪造地图点。

## 足球场专题

将球场作为独立 POI，记录稳定场地 ID、名称/别名、坐标、城市、启用/停用日期以及官方来源。俱乐部另设关联实体和有效期，支持共享主场、搬迁和更名，避免用俱乐部名称作为球场唯一键。

现有地点布尔到访适合“到过球场”。如需区分外观打卡、参观、现场观赛，需明确新事件模型（时间、活动类型、场地 ID；比赛信息可选），并设计版本迁移；不要拿行政区“到达”状态或自由备注代替可统计的观赛事件。首期可保留简单 POI 到访，球队巡礼/球场巡礼作为分开的目标集合；赛事赛程与实时球队数据另行处理。

建议交付顺序：范围注册表与迁移测试 → 一个国家一级区划与已有地点 → 官方遗产小样本 → 球场小样本与统一实体去重 → 对应成就。每一步先验证世界页和专题记录互通、计数一致、空态及缺坐标行为，再扩充数量。
