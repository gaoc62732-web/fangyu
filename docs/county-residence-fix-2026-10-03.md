# 县级居住与市州有效状态

原因：原 `visitState()` 只读取地区自身保存值。县级登记“短居／居住”时，既有祖先逻辑只保证到达，不会使所属市州显示同等居住等级。

本次仅对中国 `level=2` 县区的直属 `level=1` 市州生效，沿用现有状态等级：未到达 < 飞跃 < 途经 < 到达 < 短居 < 居住。

- 市州有效状态取其原始保存值和直属县区“短居／居住”中的最高等级；多个县取最高等级，包含历史县区的已存旅行证据。
- 派生值不写回父记录。县改为较低状态、清除或撤销时重新计算，市州手动“居住”不会因某个县清除而丢失。
- 市州状态下拉编辑原记录，另显示“地图与统计状态”；发生派生时提示原手动记录仍保留。地图、悬停、到访判断、成就和点卯统计统一读取有效值。
- 普通到达的既有祖先逻辑继续保留，但县级操作不会改写直属市州已有显式记录。没有显式父记录时的普通到达仍按旧逻辑处理。
- 不把居住等级推导到省，不向下传播其他县，不影响法国独立分层记录或其他国家专题。
- 旧存档中已保存的市州“到达”无法区分来自旧自动逻辑还是手动输入，保留原值，不猜测删除。个人名称、备注、自建地点、记录格式不变。

已验证：36种父／子状态组合，单县、多县、迁改、降级、清除与恢复、撤销、刷新、旧存档和个人字段；包括“父途经 → 县居住 → 县短居 → 县到达 → 县未到达”过程中父原值始终为途经。省级与法国隔离、历史县和直属关系均有覆盖。

浏览器证据：`data/generated/county-residence-ui/results.json`、`hangzhou-derived-resident.png`、`hangzhou-derived-mobile.png`。隔离浏览器实际操作杭州两个县区，检验市州悬停、点卯城市计数、成就、撤销和刷新；未读取用户个人浏览器记录。

领域测试 `scripts/verify-county-residence.mts`；浏览器测试 `scripts/verify-county-residence-ui.mjs`。本地开发审阅 `http://localhost:5191/#/china`，稳定5190不变。
