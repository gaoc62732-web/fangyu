## 发现的问题与迁移差异

### 1. 机场别名和跨地区候选未完整归并（P2）

位置：`packages/import-export/src/names.ts:69`、`:103`、`:119`；相关目录中的中文与英文机场具有不同的 `recordId`。

在“导入导出 → 乘降机场”分别输入以下名称：

| 输入               | 实际预览                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `PKX`              | 两个候选：中文大兴机场（北京、河北）与英文 Beijing Daxing International Airport（中国大陆）；被判为同名待选 |
| `北京大兴`         | 唯一候选，覆盖北京大兴区与河北广阳区                                                                        |
| `北京大兴国际机场` | 唯一候选，覆盖北京大兴区与河北广阳区                                                                        |
| `大兴机场`         | 唯一候选，但只有北京大兴区                                                                                  |

程序实际应用“大兴机场”后，北京侧项目已标记，河北侧仍未标记。旧版 README / v0.2.4 明确说明这四种写法应归到同一机场，并补记同一机场的跨地区条目。

原因是先按各条目的别名收集匹配，再按“代码 + 名称”分组；简称只命中部分地区，中文与英文名称又无法归并。应补充明确的同机场身份/关联，按实体展开候选，同时继续保留同码旧新机场的人工选择，不能简单把所有同码项目合并。

### 2. 个人改名会改变要素成就计数（P2）

位置：`packages/domain/src/achievements.ts:80`、`:86`。

用真实目录中同省的两条 `PEK北京首都` 项目做独立程序复现：两条都标记后，“机场行旅”为 `1 / 309`；只把其中一条的个人名称改成“个人改名测试”，到访不变，成就却变为 `2 / 310`。

动态成就按 `session.entries('china')` 返回的个人显示名称去重。显示名称覆盖不应改变公共目录实体的统计身份；应使用稳定目录身份或原始目录名称作为分组依据，并另行明确个人新增项目是否计入。

### 3. 世界页未保留旧版专题要素分流（P2）

位置：`apps/web/src/pages/CatalogPage.vue:61`、`:83`。

实际操作“世界 → 中国大陆 → 搜索 PKX”仍展示英文大兴机场；世界页选择日本也直接列出机场等项目。旧版 README、v0.2.3 与 v0.5.0 则规定：中国大陆分项在中国手册查看，日韩先显示国家状态并进入专题，不在世界页重复列示。

当前过滤只考虑范围、地区和类别，未见这些分流规则。重构文档未明确将这项旧行为列为主动取消，应恢复分流，或在产品边界中明确确认改变。此差异也扩大了机场导入中的重复候选问题。

### 4. 旧版可读的 `.osm.xml` / `.xml` 被跳过（P2）

位置：`apps/web/src/pages/ImportsPage.vue:262`、`apps/web/src/features/imports/parse.ts:107`。

旧页面地理文件入口明确接受 `.osm.xml`、`.xml`。新版仅接受并分派 `.kml`、`.osm`、`.pbf`；对包含合法 OSM XML 的合成 `sample.osm.xml` 运行 `stageGeographicFiles`，结果是 0 个文件、0 个要素，提示“格式不支持，已跳过”。

这是扩展名入口遗漏，不代表整个 OSM XML 解析器缺失。应恢复相应入口，并在解析时检查实际 XML 内容。

### 5. 导入前预设等级及记忆选择未保留（P3）

位置：`apps/web/src/pages/ImportsPage.vue:26`、`:339`、`:357`。

旧版在选择地理文件之前提供预设等级，并保存到 localStorage。新版初始导入页没有该选择，只有生成预览之后才出现“统一目标状态”；其值是组件内的 `ref('transit')`，离开导入页后不会持久保留。

预览后逐项修改和批量套用仍然存在，因此不是等级调整功能整体丢失，但缺少旧版的导入前设置与记忆行为。
