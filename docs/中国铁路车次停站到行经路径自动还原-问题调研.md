# 中国铁路“停靠站序列到行经路径”自动还原：建模问题与方案草案

## 1. 任务定义

本项目要解决的不是“证明某趟列车当天在每一股道上的真实运行轨迹”，而是一个带有不完备信息的铁路路径建模问题：

> 给定一串按运行顺序排列的停靠车站，以及可选的车次号，基于经过处理的铁路数据，计算一条最有可能的铁路行经路径，并点亮路径经过的铁路区段和行政区。

车站列表是可获得的核心输入。车次号可能有，也可能没有；即使有，车次号本身能够稳定提供的路径信息也很少，主要只有：

- 尾数或单双号对上行、下行的弱提示；
- G、D、Z、T、K 等种别对高速、城际、普速等线路偏好的弱提示。

不把车次号当作永久线路 ID，也不假设车次编号的其他数字具有稳定的空间含义。车次号存在时用于加权，缺失时模型仍应仅凭站序运行。

这里的“经过处理的铁路数据”不只是 OSM 原始数据，还包括：

- 人工修正的站名、线路名、站场连接和数据错误；
- 由大量车次、停站和线路样本总结出的统计规律；
- 用户对候选路径的选择、否决和局部修正；
- 第三方线路资料、历史记录和可复核的人工确认结果。

最终输出不是唯一真值，而是排序后的假设：

1. 最高分的最可能路径；
2. 路径中仍然不确定的区段；
3. 必要时给出若干备选路径；
4. 由所选路径几何计算出的经过行政区。

## 2. 允许的简化和不承诺的内容

为了满足“尽可能真实”而不是“绝对准确”的目标，可以明确接受以下简化：

- 不恢复完整信号联锁、闭塞和调度命令；
- 不强求确定站内具体站台、股道和每个道岔的进路；
- 不把临时施工、故障绕行和当天调度偏离作为第一阶段必须识别的事实；
- 不要求停站列表包含技术停车、待避、换挂和线路所；
- 以线路走廊或代表性轨道几何作为主要输出粒度，轨道级差异单独标记；
- 对难以确认的区段保留不确定性，不因模型必须给出结果而伪造精确细节。

如果日期能够从用户或车次数据库获得，它可以用于筛选停站和线路有效期；日期不是路径模型唯一依赖的必要输入。默认结果表达通常运行或计划路径，而不是某一天的实时运行记录。

## 3. 问题的最小集合

原调研中大量运行知识和 OSM 细节，可以压缩成以下直接影响模型的约束。

### 3.1 停站序列是离散锚点，不是连续路径

相邻停站之间可能有高速线、既有线、新旧并行线、城际线、联络线或外绕线等多条候选走廊。长距离少停站车次尤其缺少中间约束，最短距离和最少转向都不能证明是真实经由。

### 3.2 站名不等于一个唯一空间节点

同一名称可能命中不同客站、历史站址、地铁站、公交站、站房、站场面、站台或轨道上的停车位置。OSM 中 railway=station、railway=stop、public_transport=station、站台、建筑和 landuse=railway 可能分散存在，名称匹配必须先归并到标准铁路站点。

### 3.3 车站是有边界的运行设施，不是一个无向点

大型枢纽可能有多个车场、不同方向的咽喉、场间联络线和不互通的站台区。停靠同一站名不说明列车从哪一个入口进入、在哪个车场停靠、从哪一个出口离开。站内抽象必须保留主要进出组合，否则全局路径可能在站内“凭空穿越”。

### 3.4 线路身份、物理轨道和客运服务不是同一层

railway=rail way 是物理轨道对象；route=tracks、route=railway 和 route=train 分别接近基础设施聚合、铁路线路和具体列车服务。现实 OSM 中关系可能缺失、只覆盖部分成员、方向或顺序不完整，也可能出现类型误用。name、ref、railway:ref、operator、usage、service、tracks 等字段只能提供证据，不能单独证明某一车次使用该轨道。

### 3.5 OSM 拓扑、生命周期和完整性不稳定

几何相交可能没有共享节点，站场连接可能被简化，平行轨道可能合并或拆分不一致；construction、disused、abandoned 等状态还会把不同时间的对象放在当前数据库中。线路新增、改线、废弃和关系维护也可能不同步。

### 3.6 车次号只能提供弱先验

尾数和单双号可以作为方向倾向，G/D/Z/T/K 可以作为线路等级或速度类型倾向，但它们不能唯一确定线路、枢纽进路、具体方向或当天运行路径。所有车次号特征都应是软约束。

### 3.7 经过行政区需要路径几何

停靠站所属行政区不是列车经过行政区的简单并集。应将最终候选路径几何与行政边界相交，并明确当前边界或旅程日期边界；桥梁、隧道、边界河道和站场范围会带来小段相交歧义。

### 3.8 结果必须允许多解和修正

没有完整运行图时，多条路线可能同样合理。系统需要表达 Top-1、Top-k、区段级可信度、数据断点和“站内连接未知”，否则用户会把猜测误解为官方事实，用户反馈也无法用于改进。

## 4. 建模层次

建议把原始资料、推断网络和最终展示分开建模。

| 层次 | 对象 | 主要作用 |
| --- | --- | --- |
| 输入观察 | TripObservation | 原始站名序列、可选车次号、可选日期、来源 |
| 标准站点 | Station | 站名别名、历史名称、OSM 对象、站场范围、行政区 |
| 线路走廊 | Corridor | 工务/运营意义上的主线、支线、联络线和名称归并 |
| 简化拓扑 | Gateway、Junction、Segment | 站场进出、分岔和站间可用连接 |
| 路径假设 | RouteHypothesis | 一条完整候选、证据、得分、数据版本和不确定性 |
| 展示结果 | OSM 几何、行政区交集 | 点亮铁路区段和经过的行政区 |

### 4.1 标准站点和别名

每个 Station 至少保存标准名称、别名、历史名称、客运站/乘降所类型、坐标或站场范围、对应 OSM 对象列表、所在行政区和有效时间。多个 railway=stop、站台和车场可以挂在一个标准站点下，但不能因此把所有轨道合并成一个节点。

站点可附带若干 Gateway。网关表示客运车场或站场方向与哪些线路走廊相连，是把“车站名称”转成“铁路网络端点”的关键。没有网关资料时，也可以从站点附近轨道生成低可信度候选。

### 4.2 线路走廊和区段

Corridor 是推断用的中等粒度线路对象，不等于一个 OSM way，也不等于一个车次关系。它可由多条连续 OSM way 组成，保存：

- 标准线路 ID、名称变体和来源；
- OSM way/relation 成员及有效期；
- 主线、支线、联络线、站场连接等类别；
- 运营状态、轨距、电气化和速度等辅助属性；
- 人工确认和统计推断的可信度。

Segment 是两个站点、网关或关键分岔之间的计算区段，保存几何、长度、方向、转向角、所属走廊、可用日期、拓扑状态和数据质量。算法在 Segment 或 Corridor 层选择路径，最后才展开到具体 OSM way。

### 4.3 规律、人工修正和用户反馈

所有外部知识都应作为可追溯的证据保存，而不是直接改写 OSM 真值：

- 人工维护：站名映射、线路归并、站场网关、已知折角和断点桥接；
- 统计规律：不同车次种别、方向、站间组合、线路组合的历史频率；
- 用户反馈：接受、否决或替换某个候选区段；
- 来源信息：来源、采集时间、有效日期、人工确认状态。

这样可以区分“铁路数据本身的事实”和“系统根据样本形成的偏好”。

## 5. 分阶段的可行方案

### 阶段 A：规范化停站输入

1. 接收有序车站列表；如果有车次号，提取种别和尾数方向先验，但不把车次号当线路标识。
2. 用别名、历史名称、拼音、人工映射把原始站名归并到标准 Station。
3. 一个名称对应多个站点时保留候选，并要求用户选择或降低该段可信度。
4. 标记列表是否完整、是否可能只是某个车次的子序列、是否有重复站名或折角站。
5. 若车次数据库能提供更完整的停站序列，用它校验用户输入；若车次号缺失，直接以用户给定列表继续推断。

这一步得到的是带站点候选的有序锚点，还不是物理路径。

### 阶段 B：预处理 OSM 和人工铁路数据

1. 选取铁路轨道对象，排除明显的地铁、道路和与目标日期不符的生命周期对象；可能是站线、货场线或联络线的对象单独标记，而不是直接删除。
2. 合并连续 way 的几何，识别未共享节点、几何相交、平行轨道、缺失端点和明显错误连接。
3. 使用工务线路名、OSM 名称变体、已有 relation 和人工归并表把轨道归入 Corridor。
4. 在客运站、车场边界和重要分岔处生成 Gateway、Junction 和 Segment。
5. 对 OSM 缺口建立带来源和低可信度的可能连接或人工桥接，不能把推断连接伪装成原始 OSM 拓扑。

目标是得到一个能够表达主线、支线、联络线和主要站场连接的走廊图，而不是完整信号联锁图。

### 阶段 C：生成站间候选

对每一对相邻停站生成多条候选路径，并按约束逐步放宽：

1. 同一 Corridor 连续连接两个站点；
2. 少量主线或已知联络线组合；
3. 经过枢纽网关、折角或支线的拓扑可行路径；
4. 使用人工桥接或低可信度 OSM 连接的补全路径。

每条候选记录长度、预计时间范围、走廊数量、主支线比例、转向次数、绕行比例、数据缺口和端点网关。最短、最快、名称最连续的路径都只是候选来源。

### 阶段 D：对候选进行软约束评分

可以把一条站间候选或完整路径的得分抽象为：

    Score(P) =
        w1 * station_match
      + w2 * corridor_continuity
      + w3 * schedule_fit
      + w4 * train_type_fit
      + w5 * direction_fit
      + w6 * gateway_fit
      + w7 * historical_frequency
      + w8 * user_evidence
      - w9 * detour_penalty
      - w10 * branch_penalty
      - w11 * turn_penalty
      - w12 * data_uncertainty

硬约束只保留明显不应违反的条件：站序顺序、基本铁路连通、站点能落到目标网络、明确不开放的对象和明显错误的交通方式。

软约束包括：线路名称连续性、主线偏好、里程和时间合理性、G/D/Z/T/K 种别、车次尾数方向、站场网关、转向角、复线左行倾向、历史频率、用户反馈和数据质量。

“尽量直行”和“复线通常左行”应是软约束。它们可以在多个可行连接中排序，但不能单独否定有铁路设施支持的连接。车次种别和尾数也必须是弱先验，不能硬编码成线路规则。

初始权重可以由人工规则给出；得到人工核验样本和用户反馈后，再按车次种别、方向、线路类别和站间场景校准。权重和训练/统计数据都需要版本化。

### 阶段 E：对全程进行全局选择

每个站间独立选最高分，可能导致同一枢纽前后选择互不衔接的线路。因此要把相邻站间候选一起评估：

- 状态至少包含当前站点的进出网关、当前走廊和是否处于折角/换向状态；
- 相邻区段共享网关时奖励连续线路和合理站内转接；
- 可用动态规划或束搜索保留前若干条完整路径；
- 对 A-B-C，先生成 A-B 和 B-C 候选，再用进出方向、转向角、站场网关和方向先验判断正常通过、折角或换向；
- 站内连接不清楚时保留“站场内未知”，不虚构具体股道。

最终得到 Top-1 和 Top-k 完整路径，并把不确定性定位到具体区段。

### 阶段 F：展开几何并计算行政区

1. 将所选走廊和区段映射到 OSM way，合并制图切分造成的视觉断裂。
2. 多股平行轨道无法区分时，输出走廊级代表几何或并列候选，并标记轨道级不确定性。
3. 站场内部使用典型连接几何或站场范围，不把抽象网关画成精确股道。
4. 将路径几何与行政区多边形相交，按可用日期选择当前或历史边界。
5. 对桥梁、隧道和极小的边界擦边保留相交记录和过滤阈值，避免结果对几何噪声过敏。

行政区结果应注明是“路线几何相交所得”，不是停靠站所属地的简单并集。

## 6. 用户反馈和规律学习

用户反馈是经过处理数据的一部分，但不能简单把用户频次当作真值。

### 6.1 反馈粒度

反馈至少关联到：原始站序、车次种别和方向、日期（若有）、候选区段、用户选择、数据版本。优先记录用户否决或替换的具体区段，不把整条路径的选择平均传播到所有区段。

### 6.2 规律统计

可以按以下条件统计候选路线的出现或被接受频率：

- 相邻标准站点；
- 车次种别和方向；
- 线路走廊组合；
- 枢纽和折角状态；
- 日期或运行图时期；
- 数据来源和人工确认级别。

统计结果应作为 historical_frequency 或先验分数，且设最小样本量、时间衰减和人工覆盖规则，避免少量用户偏好长期压过明显的铁路拓扑证据。

### 6.3 人工维护优先级

优先维护会明显改变候选排名的对象：

1. 同名站、历史站名和站点到标准 Station 的映射；
2. 工务线路名及 OSM way/relation 到 Corridor 的归并；
3. 大型枢纽的客运车场、进出网关和已知折角；
4. 高频歧义区段、主支线分岔和 OSM 拓扑断点；
5. 少量人工确认的完整车次作为评分校准样本。

技术停车点、每个站台的股道和每次临时改线可以作为后续增强，不应成为第一阶段给出走廊级结果的门槛。

## 7. 结果表达和失败处理

推荐结果应显示日期和停站输入、最高分线路组合、经过行政区、主要依据和不确定区段。Top-1 与 Top-2 分差很小时，应明确显示“存在多条同样合理的路径”。

可信度可以拆成：

- 站名和站点匹配可信度；
- 站间走廊选择可信度；
- 站场网关/折角判断可信度；
- OSM 几何和拓扑质量；
- 行政区相交可信度。

常见失败状态不应被隐藏：

- 站名无法唯一匹配；
- 两个站点之间没有可信拓扑路径；
- 只找到依赖人工桥接的低可信度路径；
- 全程存在多个分数接近的候选；
- 车次号缺失或只提供弱先验；
- OSM 当前数据与目标日期不一致。

这些情况下仍可展示最高分候选，但必须标记推断性质，并允许用户只修正不确定区段。

## 8. 评价方法

“最有可能”必须用人工核验样本评价，而不能只看地图是否连通。样本应覆盖高速和普速、长距离少停站、新旧并行线、枢纽折角、支线接入、复杂站场和 OSM 缺口区域。

至少评价：

- 站名归一化成功率和人工二次选择率；
- 站间候选的 Top-1、Top-k 走廊命中率；
- 全程路径连续性和错误换线次数；
- OSM 几何覆盖率、断点率和人工桥接比例；
- 经过行政区的精确率和召回率；
- 用户接受 Top-1、选择备选、否决全部候选的比例；
- 引入人工维护和反馈后，同类站间区段的推荐改善程度。

评价要区分“走廊级正确”和“股道级正确”。当前目标应优先验证走廊级和行政区级结果，股道级只作为有额外站场资料时的增强指标。

## 9. 推进顺序

### 第一步：最小可用闭环

完成站名归一化、人工线路归并、站间候选生成、Top-k 排名、OSM 几何展开和行政区相交。此阶段允许站内网关简化、允许低可信度桥接，并展示不确定性。

### 第二步：高影响数据维护

根据候选分歧和用户否决集中位置，补齐同名站、主支线分岔、枢纽进出网关、折角站和 OSM 断点。

### 第三步：统计和反馈校准

按车次种别、方向、线路类别、日期和站间场景校准评分权重；反馈按区段和场景聚合，不把单个选择固化为线路真值。

### 第四步：细节增强

再处理技术停车点、站台/股道、历史边界、临时运行图和更细的桥隧表达。这些增强提高可信度，但不改变第一阶段的基本目标。

## 10. 暂时不承诺

在没有内部运行图、调度记录和完整站场联锁数据时，系统不承诺：

- 还原当天具体股道和信号进路；
- 识别所有技术停车、待避、换挂和调车动作；
- 证明临时改线或故障绕行是否发生；
- 仅凭车次号消除所有历史版本和途中换号歧义；
- 把 OSM 中每一条轨道解释成该车次可以使用的运行线。

这些限制不妨碍走廊级路径还原，但产品必须区分“最可能的通常路径”和“当天实际运行记录”。
